- Cloudflare Pages hosts the static Next.js frontend at `defibar.finance`. Railway US East hosts the GraphQL API at `api.defibar.finance`, private MongoDB `defibar`, and the daily updater. There is no root npm workspace. Use Node 24.21.0 and npm 11. Run package commands from `frontend/` or `backend/`; see their READMEs.
- Pages builds `frontend/` with `npm run build` and publishes `out/`. GraphQL Codegen reads `../backend/src/**/*.graphql`, so it needs the full checkout. `NEXT_PUBLIC_API_URL` and `NEXT_PUBLIC_APP_URL` are build-time public values. The API CORS policy allows the production origin and this project's `pages.dev` branch/deployment origins.
- Railway app services build from `backend/`. The API uses `npm run start:prod` and `/health`; the updater uses `npm run update:protocols`, restart policy `NEVER`, and cron `0 5 * * *` UTC. Its CLI validates feed size and ID overlap before writes, then exits. Inspect each scheduled deployment's completion log, not only its status. The first scheduled run succeeded at 05:01 UTC with 8,950 documents.
- Railway sources were pinned to commit SHAs during migration. Inspect source settings and advance the API and updater deliberately when releasing; changing the API source should not cause an updater run. Pages also has a production branch setting that must follow the final branch after merge.
- The database has no public TCP proxy or managed backups. `README.md` documents a private Railway tunnel and manual BSON dump/restore. The Railway CLI's `connect --tunnel-only` prints the password: suppress its output in logs. Keep archives private and Git-ignored under `.migration-backups/`. The protocol dataset can also be rebuilt by the updater.

Localhost may require sandbox escalation.
